# 宿泊管理システム（hotel-pms）

らく通の「予約一覧」CSV を取り込み、インジケーター（客室マップ）で部屋を割り当てて、チェックイン・チェックアウトと精算を行う宿泊管理システムです。
画面の設計は、別途作成した画面モックに合わせています。

## いまできること

| 画面 | 内容 |
|---|---|
| ダッシュボード | 今夜の稼働率、本日の到着・出発・入金、部屋タイプ別の残室、要対応（部屋割り待ち・未収・取り込みの遅れなど） |
| インジケーター | フロアごとに部屋を並べ、状態を色で表示。件数つきチェックで絞り込み。部屋にカーソルを合わせると宿泊者情報、クリックで固定表示。部屋割りが必要な予約を選んで空室をクリックすると割り当てる（自動の部屋割りもあり） |
| 予約 | 取り込んだ予約の一覧（宿泊日・区分・エージェント・お客様名などで検索、部屋割りが済んでいない予約だけの表示）と予約詳細（入金・預り金の内訳つき） |
| チェックイン精算 | 予約一覧・予約詳細・インジケーターから開く。未収の宿泊料等と預り金をまとめて受け取り、チェックイン済みにする。支払方法は現金・クレジットカード・QR決済・電子マネーで、ブランド（VISA、PayPay、交通系IC など）を必ず記録する |
| 預り金の登録 | 滞在中の予約に預り金（前預かり）を追加する |
| チェックアウト | 未収が無いことを確認し、預り金の残りを返金してチェックアウト済みにする |
| らく通 CSV 取込 | CSV をアップロードして取り込み。「確認のみ」で事前チェックができる。同じ予約は上書きされ重複しない |
| 在庫 | 部屋タイプ別の残室を 2 週間分表示（客室マスタの部屋数 − 予約の室数）。マスをクリックするとその夜の予約を表示 |
| フロント会計（集計） | 1 日の入金・預り金・返金を支払方法とブランド別に集計。取引一覧とレジ締め（理論在高と実査の過不足） |
| レポート | 期間の稼働率・宿泊売上・ADR・RevPAR・取消、日別の稼働率グラフ、エージェント別・部屋タイプ別・決済方法別 |
| 客室マスタ・設定 | 部屋の手入力での登録（例：`201-216 禁煙シングル`）、部屋タイプ名の一括変更（らく通の部屋タイプから選択も可）、故障の設定、施設名の変更、サンプルデータの削除 |

インジケーターの色は次のとおりです。

| 色 | 状態 |
|---|---|
| 紫 | 滞在中 |
| ベージュ | 滞在中で翌日出発 |
| ベージュ・太枠 | 本日出発予定（まだチェックアウトしていない） |
| 緑 | アサイン済み未到着 |
| 白・点線 | チェックアウト済 |
| 白・実線 | 空室 |
| 赤 | 故障 |
| 右上の点 | フロント備考あり |

## 営業日とナイトオーディット

- 画面の「今日」は、カレンダーの日付ではなく**営業日**です。左のメニューにいつも表示されます。
- 営業日は自動では変わりません。一日の業務が終わったら、ダッシュボードの「営業日を締めて翌日へ（ナイトオーディット）」で翌日へ進めます。
- 進める前に、未チェックイン・未チェックアウト・未収・部屋割り・レジ締めの確認が表示されます（確認が残っていても進められます）。
- チェックインできるかの判定、フロント会計の 1 日の区切り、各画面の最初の日付は、すべて営業日で決まります。深夜 0 時を過ぎても、営業日を進めるまでは前日の扱いです。
- 入金には受け取った営業日を記録し、フロント会計とレポートはその日で集計します。
- 押し間違えたときは「客室マスタ・設定」の「営業日」で直せます。ナイトオーディットの履歴もそこで見られます。
- 「客室マスタ・設定」の「データのリセット」で、予約・入金などをすべて削除して営業日を決め直せます（客室マスタは残ります）。

## 必要なもの

- Node.js 22（LTS）
- WebStorm（または IntelliJ IDEA Ultimate）

データベースは SQLite（ファイル 1 つ）を使うので、別途インストールは不要です。

## はじめかた（WebStorm）

1. **Node.js を入れる**
   https://nodejs.org/ から「LTS」の macOS インストーラーをダウンロードして実行します。
   WebStorm の「設定 → 言語 & フレームワーク → Node.js → Node インタープリター」の「ダウンロード」からも入れられます。
2. **WebStorm でこのフォルダを開く**
3. **WebStorm 下部の「ターミナル」で次を順に実行する**

   ```bash
   npm install
   cp .env.example .env
   npx prisma migrate dev
   npm run dev
   ```

   Windows の場合は `cp .env.example .env` の代わりに `copy .env.example .env` を実行します。

   `npx prisma migrate dev` でデータベースが作られ、`data/rooms/` の客室マスタ（古河駅前 292 室）が登録されます。予約は空の状態で始まります。
   架空のサンプル予約で試したいときは、`.env` に `SEED_SAMPLE=1` を書き足してから `npm run db:reset` を実行します（サンプル用の 32 室と予約が入ります）。
4. **ブラウザで http://localhost:3000 を開く**

## らく通のデータを取り込む

1. らく通で「予約一覧」を CSV で出力します。Excel で開いて保存すると電話番号などが壊れるため、出力したままのファイルを使ってください。
2. 画面左の「らく通 CSV 取込」でファイルを選び、まず「確認のみ」で取り込みます。
3. 注意点を確認してから「確認のみ」を外して、もう一度取り込みます。

サンプル予約は「客室マスタ・設定」の「サンプル予約を削除」で消せます。

データベース（`prisma/dev.db`）は Git に含めていません。複数の PC で同じデータを使うときは、次の「複数の PC で使う」のとおり 1 台をサーバーにします。
コマンドで取り込むこともできます。

```bash
npm run import:csv -- data/private/予約一覧.csv --dry-run
```

### 個人情報の扱い

- らく通の CSV とデータベース（`prisma/dev.db`）にはお客様の個人情報が入ります。
- 実データの CSV は `data/private/` に置いてください。このフォルダとデータベースは Git の管理対象から外してあります。
- `data/sample/` の CSV は架空の宿泊者で作ったものです。

## 複数の PC で使う（同じデータを共有する）

データベースはサーバーにする PC の中に 1 つだけ置き、ほかの PC はブラウザで開きます。ほかの PC には何も入れる必要はありません。

1. サーバーにする PC（電源を入れたままにできるもの）で「はじめかた」の 1〜3 の `npx prisma migrate dev` までを行います。
2. 次のコマンドで起動します（本番用にビルドして、ほかの PC から接続できる設定で起動します）。

   ```bash
   npm run serve
   ```

3. サーバーの PC の IP アドレスを調べます（Mac：「システム設定 → ネットワーク」、Windows：コマンドプロンプトで `ipconfig`）。
4. ほかの PC のブラウザで `http://（サーバーの IP アドレス）:3000` を開きます（例：`http://192.168.1.20:3000`）。

- 同じ店内のネットワーク（Wi-Fi・LAN）につながっている PC から開けます。インターネットには公開されません。
- 初回は、サーバーの PC でファイアウォールの許可を求められたら「許可」を選びます。
- サーバーの IP アドレスが変わらないよう、ルーターで固定しておくと便利です。
- データはサーバーの PC の `prisma/dev.db` に保存されます。定期的にこのファイルをコピーしてバックアップしてください。
- 現時点ではログインの仕組みがないため、店内ネットワーク以外からは開けないようにしてください。

### 客室マスタ（`data/rooms/`）

- 施設と客室は `data/rooms/*.csv` から登録します（列：施設,部屋番号,階,館,タイプ,タイプ記号,定員）。部屋番号・タイプなどの設備の情報だけで、お客様の情報は入っていません。
- `npx prisma db seed` を実行すると、まだ無い部屋だけを追加します（既にある部屋や予約は変わりません）。
- 別の店舗で使うときは、その店舗の客室マスタの CSV を `data/rooms/` に追加します。

## ポータブル版（インストール不要で動く版）

WebStorm や Node.js を入れられない PC 向けに、展開してダブルクリックするだけで動く版を作れます。作成は Mac で行います。

```bash
npm run build:portable
```

`dist/` に次の 2 つができます。

| ファイル | 対象 |
|---|---|
| `hotel-pms-win-x64.zip` | Windows（64 ビット） |
| `hotel-pms-mac-arm64.zip` | Mac（Apple Silicon） |

- 中身は Node.js 本体、ビルド済みのアプリ、初期データベース、起動ファイル、説明書（README.txt）です。
- 初期データベースには、この PC の `prisma/dev.db` から施設と客室マスタだけをコピーします。予約・入金・預り金はコピーしません。
- 架空のサンプルデータで作るときは `npm run build:portable -- --sample` を実行します。この PC にデータベースが無いときは `data/rooms/` の客室マスタで作ります。
- 別の PC では zip を展開し、Windows は `start-hotel-pms.bat`、Mac は `start-hotel-pms.command` をダブルクリックします。
- データはポータブル版のフォルダ内の `data/hotel.db` に保存されます。その PC の中からだけ開ける設定です。
- 現時点では、データベースの構造が変わる更新には対応していません。新しい版に入れ替えるときは事前に相談してください。

## コマンド

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発用サーバーを起動（http://localhost:3000） |
| `npm run serve` | 本番用にビルドして、ほかの PC から接続できる設定で起動（店内での共有用） |
| `npm test` | CSV 読み込みと客室状態の判定のテスト |
| `npm run typecheck` | 型チェック |
| `npm run build` | 本番用ビルド |
| `npm run build:portable` | ポータブル版（Windows・Mac）の zip を `dist/` に作る |
| `npm run db:reset` | データベースを作り直して客室マスタを入れ直す（予約・入金はすべて消える） |
| `npx prisma db seed` | 客室マスタ（`data/rooms/`）のうち、まだ無い部屋を追加する |
| `npx prisma studio` | データベースの中身をブラウザで見る |

## 構成

- Next.js 15（App Router）＋ TypeScript
- Prisma ＋ SQLite（本番では `prisma/schema.prisma` の provider を `postgresql` にして PostgreSQL へ移行）
- 金額はすべて整数の円、日付は `YYYY-MM-DD` の文字列で扱う

```
src/lib/rakutsu-csv.ts     らく通 CSV の読み込み（列は見出し名で探す・UTF-8 と Shift_JIS 対応）
src/lib/import-rakutsu.ts  データベースへの取り込み
src/lib/indicator.ts       インジケーターの客室状態の判定
src/app/                   各画面
prisma/schema.prisma       データ定義
```

### らく通の取り込みとの関係

- 同じ予約は予約番号で判定し、取り込み直すと最新の内容に上書きします。
- この画面で行った部屋割り・チェックイン・チェックアウトと入金・預り金は、取り込み直しても消えません。
- 取消の予約は取り込みません。取り込み済みの予約がらく通で取消になったら、部屋割りごと削除します（チェックイン済み・入金ありの予約は記録を残すため削除せず、注意を表示します）。
- 決済方法に「現地」が含まれる予約（現地決済・現地精算）だけ、チェックイン時に料金を受け取ります。それ以外（事前決済・法人決済など）は受け取りません。
